# 文章圖片共同視覺規範

封面與 AI 生成的內文插畫、流程圖、架構圖及前後對照圖共用此風格。真實截圖、照片與數據圖表保留原始資訊，不為了統一風格而重繪成實測證據

## 全站視覺語言

### 插畫風格

- 使用精緻的 soft-3D 編輯插畫，以黏土感的數位造型、簡化且圓潤的幾何形式呈現
- 材質以平滑霧面塑料為主，搭配細膩的立體明暗；避免過度光亮
- 採略帶等角透視感的 2.5D 視角，整體現代、專業且成熟，不走幼稚可愛路線
- 風格化而非寫實，維持 SaaS、開發者工具與科技媒體常見的乾淨質感

### 色彩與光線

- 背景配色依當篇文章主題決定；同一張圖的背景、主體與點綴色需形成一致且能呼應主題的色彩系統
- 使用柔和環境光、陰影與輕微 bloom，重要物件可加入明亮輪廓光
- 可用少量高對比色作為視覺重點，但避免每個物件都使用過多漸層
- 保留柔和的體積光與適度景深，主體必須清晰

### 構圖與內容

- 以一個清楚的核心物件或概念作為視覺主角，周圍配置與主題相關的輔助物件
- 構圖平衡並保留充足負空間，以前景和背景元素建立細微景深，確保縮圖與中央裁切時仍有明確層級
- 背景可加入少量抽象科技 UI 元素、粒子、連接線或幾何形狀，但不可造成視覺雜亂
- 技術主題可依內容選用程式碼視窗、終端機符號、資料庫、雲端服務、伺服器、API 連線、開發工具、瀏覽器視窗、齒輪、節點、游標或抽象軟體圖示
- Logo、品牌名稱與指令名稱可在符合文章內容時出現，且應作為主題資訊的一部分；文字規則依封面或內文圖用途處理

### 品質與避免事項

- 畫面需細緻到具有高品質、成熟的 3D 編輯插畫質感，但不堆疊無關細節
- 生成後確認必要識別確實出現、與官方來源一致且在縮圖尺寸仍可辨認；缺漏、變形、拼錯或出現未指定品牌時不採用
- 避免照片寫實、平面向量、動漫、手繪、幼稚卡通、過度光亮材質，以及與主題無關的隨機裝飾物

## 已確認的參考圖

- [Hermes Agent Telegram 個人助理封面](../../../posts/2026-08-28-hermes-agent-telegram-assistant/cover.jpg) （2026-08-28）：可重用的特徵是 soft-3D、圓潤霧面造型、深色乾淨背景、中央主角與在縮圖尺寸仍清楚的視覺層級
- 圖中的 Hermes Agent 官方形象、MacBook、Telegram 識別與配色是該篇文章的內容需求，不視為其他文章必須沿用的全站元素

## 同篇文章的一致性

- 封面與內文生成圖使用相同的材質、光線、主題色系與物件造型；同名產品與設備的外觀、品牌識別保持一致
- 已有封面或內文圖時，先檢視作為風格參考，再製作下一張；尚無封面時，先確立主題配色與視覺語言，後續封面沿用，不因順序不同另換風格
- 不把單篇文章的深藍、青色等主題配色固定成全站要求
- 生成前依官方來源核對必要品牌名稱與 Logo；只禁止無關識別，不使用一律排除所有品牌的 prompt

## 依用途調整

- 封面：尺寸、文字限制與裁切要求另讀 [OG image 規格](../blog-publisher/references/og-image-style.md)
- 內文插畫：沿用封面風格，依內容決定比例，不強制套用封面的 1200 × 630
- 流程／架構圖：用清楚的節點與箭頭呈現關係，可加入必要的名稱、步驟與短標籤；文字須正確且在文章顯示寬度下可讀，立體效果不得遮住資訊
- 前後對照圖：前後使用相同視角與比較範圍，凸顯內文描述的變化；示意畫面與非實際數據須在圖片或圖說標示，不冒充實際截圖
- 真實截圖：需要展示實際結果時才連線擷取，先處理憑證與個資；不為了取得配圖，擅自修改家中設備或儀表板
  - 畫面含 Webhook 網址、Token、Chat ID 等機密時，先在畫面上遮蔽再擷取；示範用的值統一寫成 `<TOKEN>` 這類示意值
  - iOS 畫面可用模擬器擷取：語言設為正體中文，深淺色模式與同篇實機截圖一致，裁切到重點區塊後寬度約 600px

## 製作與驗收

- AI 生成的點陣圖使用 `imagegen` skill，prompt 明確帶入共同風格、同篇配色、用途、必要文字與禁止內容
- 草稿內文圖可在編輯階段製作，存於 `drafts/<working-slug>/`；正式發布後依 README 的圖片管線管理，不手動改建置產物
- 生成後檢查風格一致、品牌拼字、流程方向、圖文對應與可讀性；示意圖不得暗示尚未發生的實測或操作
- 檢查物件空間關係合理：家具、設備等物件不得互相穿插、懸空或錯誤包覆
- 既有圖片通過驗收就沿用，不因更新規範自動重生；OG 圖的定稿與採用仍由 blog-publisher 處理
